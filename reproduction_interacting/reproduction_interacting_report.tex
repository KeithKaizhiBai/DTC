\begin{abstract}
This report documents the interacting-stage reproduction of the nonsymmorphic discrete-time-crystal model. The calculation adds nearest-neighbor Ising interactions to the previously reproduced two-level drive, validates the implementation on the local RTX 4090 GPU, and incorporates an \(L=8\) long-time H100 run for the stroboscopic diagnostic \(Z(n)\).
\end{abstract}

\section{Scope}

The goal is to reproduce the interacting behavior discussed around Fig.~4(b--d) of Hu, Fu, Li, and Shen, \emph{Physical Review Research} \textbf{5}, L032024 (2023). The local calculation is intentionally small: it verifies the model, observable definitions, parameter choices, and qualitative DTC response. The cluster calculation then focuses on the \(L=8\) long-time stroboscopic behavior.

\section{Hamiltonian}

The interacting chain Hamiltonian is
\begin{equation}
H(t)=\sum_{i=1}^{L}H_{0,i}(t)
 + J\sum_{i=1}^{L-1}\sigma_x^i\sigma_x^{i+1},
\label{eq:interacting-h}
\end{equation}
with open boundary conditions and
\begin{equation}
H_{0,i}(t)
=\frac{1}{2}\Omega\sin(t)\sigma_x^i
 +\Omega\sin^2\left(\frac{t}{2}\right)\sigma_y^i.
\end{equation}
The dimensionless convention is
\[
\hbar=1,\qquad \omega=1,\qquad T=2\pi,\qquad \Omega=\alpha/8.
\]
The interaction direction is \(\mu=x\), matching the main-text interacting figure. The interaction strength is
\[
J/\hbar\omega=0.2.
\]

Two values of \(\alpha\) are used:
\[
\alpha=81.60,\qquad \alpha_{13}=80.04624211689759.
\]
The first is the detuned value used in the main-text finite-size lifetime plot, while the second is the refined special value near the paper's tabulated \(\alpha_{13}\approx 80.07\).

\section{Initial State and Observables}

The initial state is the product state polarized in the \(+x\) direction,
\begin{equation}
|\psi(0)\rangle=\bigotimes_{i=1}^{L}|+x\rangle_i.
\end{equation}
The primary observable is the average \(x\)-magnetization,
\begin{equation}
m_x(t)=\frac{1}{L}\sum_{i=1}^{L}
\langle\psi(t)|\sigma_x^i|\psi(t)\rangle.
\end{equation}
At stroboscopic times \(t=nT\), the reported DTC order diagnostic is
\begin{equation}
Z(n)=(-1)^n m_x(nT).
\end{equation}
If the response is period-doubled and stable, \(Z(n)\) remains positive and slowly varying over a long time window.

\section{Numerical Method}

The local calculation uses an exact state vector of dimension \(2^L\). Instead of constructing dense Hamiltonian matrices, the script applies the Hamiltonian to the state by precomputed bit-flip index arrays:
\begin{itemize}
  \item \(\sigma_x^i\) flips one bit;
  \item \(\sigma_y^i\) flips one bit with the appropriate \(\pm i\) phase;
  \item \(\sigma_x^i\sigma_x^{i+1}\) flips two neighboring bits.
\end{itemize}
This keeps the implementation transparent while allowing small GPU simulations. Time evolution uses fourth-order Runge--Kutta with per-step normalization. The normalization controls accumulated RK4 norm drift during many-period runs; the saved diagnostics still report the observed norm error after normalization.

For the long-time HPC run, direct step-by-step evolution to \(10^5\)--\(10^8\) periods would be inefficient and would produce unnecessarily large output files. Instead, the code constructs the one-period Floquet operator for \(L=8\) using midpoint matrix exponentials over one drive period, diagonalizes this \(256\times256\) unitary matrix, and evaluates \(Z(n)\) at logarithmically spaced stroboscopic periods. This is why the \(L=8\) cluster job can finish quickly while still probing the relevant period range.

\section{HPC Long-Time Result for \(L=8\)}

The cluster run used one NVIDIA H100 80GB GPU on node \texttt{gpuh14}. The Slurm launcher excluded \texttt{gpuh01}. The time-trace part used \(L=8\), 40 periods, and 120 time steps per period. The stroboscopic part used the Floquet logarithmic-sampling mode:
\[
\alpha=81.60:\ n_{\max}=10^5,\qquad
\alpha_{13}=80.04624211689759:\ n_{\max}=10^8.
\]
Both cases retain a dominant Fourier peak at \(\tilde{\omega}/\omega=0.4998958550\) in the first 40 periods, consistent with period doubling.

\section{HPC Package and Larger-System Parameters}

The upload package contains the Python script, local and HPC parameter files, a bash launcher, and empty \texttt{logs/} and \texttt{results/} directories. The HPC launcher includes
\[
\texttt{\#SBATCH --exclude=gpuh01}
\]
so that the old-CUDA \texttt{gpuh01} node is excluded.

\subsection*{How to Change the Next Run}

The main file to edit is \texttt{params/interacting\_params\_hpc.json}. For a larger system, change only the stroboscopic length list and, if needed, the maximum sampled periods:
\begin{verbatim}
"stroboscopic": {
  "lengths": [10],
  "periods_by_alpha": {
    "alpha_81p60": 100000,
    "alpha_13": 10000000000
  },
  "steps_per_period": 120,
  "sampling_mode": "log_floquet",
  "linear_prefix_periods": 200,
  "log_sample_count": 1600
}
\end{verbatim}
For \(L=10\), the Floquet matrix dimension is \(2^{10}=1024\), which is still realistic on an H100 but more expensive than the \(L=8\) run. For \(L=12\), the matrix dimension is \(4096\), and the dense Floquet path may become memory- and time-intensive because it repeatedly exponentiates dense matrices. A pragmatic next step is therefore \(L=10\) before attempting \(L=12\).

\section{Limitations and Next Step}

The current long-time run is only for \(L=8\), so it does not yet reproduce the full finite-size lifetime scaling inset of Fig.~4(c,d). The next step is to repeat the same Floquet logarithmic-sampling workflow for \(L=10\), then compare the threshold period \(n_c\) against the \(L=8\) result. If the \(L=10\) dense Floquet run remains affordable, \(L=12\) can be attempted afterward.
